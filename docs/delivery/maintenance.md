# F 專用版本維護流程

這個儲存庫是正式功能的獨立交付版本，不是原工作區的完整備份；來源只有已提交正式檔案，白名單见 [manifest](manifest.json)。

1. 在完整本機來源完成正式功能、測試與提交，不直接 push 原 main 到這個遠端。
2. 建立新的唯一隔離目錄；由已提交來源逐檔匯出白名單，不複製原 .git、未提交檔案、環境或暫存。
3. 整理 F 專用 README、進度、features 與測試；更新 manifest copy SHA-256 和来源 commit，不改寫保存結果來迎合雜湊。
4. 新副本與正式 Git 快照分別跑完整測試、指紋、UI-only 及文件連結檢查，審查敏感資訊。
5. 將核准變更帶入既有交付 checkout，正常提交和 push main；不 force push、不重置遠端歷史、不把原始來源 repo refs 帶入。
6. 從 Private 遠端取得乾淨副本再驗證；更新實際交付證據，不以舊測試結果冒充新版本。
7. 保留交付 checkout，未推送內容不能隨暫存清理刪除；它可由遠端 clone 還原已推版本，但不保存原來源專案的其他內容。

網站維持本機，啟動時綁定 127.0.0.1；若未來要雲端／公開或邀請他人，需另行決定權限、授權與平台，不自動執行。
